# World Owner Contract

Date: 2026-04-17

## Purpose

This document defines runtime ownership boundaries for the Expo world so future work stops relying on broad render-time suppression as a primary design tool.

This contract is binding for Codex implementation work unless a later accepted checkpoint explicitly replaces it.

## General Rules

1. Source-owner correction is preferred over render-layer hiding.
2. Hidden ID lists are temporary quarantine tools, not the final architecture.
3. If a world task changes booth behavior, it must do so only through shared reserve/clearance contracts unless the task explicitly includes booth files.
4. Booth branches must not change world owners.
5. World branches must not change booth placement logic except where the current task explicitly updates the reserve contract or collision validation boundary.

## Owner Boundaries

### 1. WorldCitySkeletonLayout.ts

Owns:
- generated city source data
- city planes
- city masses
- city towers
- city screen surfaces and sockets
- canonical world reserve contract input function

Does not own:
- final render-time suppression policy
- booth visual behavior
- rear-campus runtime mesh composition

Required direction:
- emit typed source categories wherever possible
- stop relying on name substrings as the long-term owner model

### 2. WorldCitySkeleton.tsx

Owns:
- aggregation of builder outputs
- minimal structural filtering
- section visibility toggles
- debug/inspect source registration for city layer

Does not own:
- district sculpting by large hidden-ID graveyards
- permanent pattern-based clutter suppression as world design
- signature skyline composition

Allowed suppression:
- only temporary quarantine items with explicit follow-up source-owner cleanup

### 3. WorldCityMasses.tsx

Owns:
- rendering of city mass source entries
- category-based secondary composition for masses

Does not own:
- district cleanup by string-match hacks
- left/right/middle region-specific sculpting logic
- source-owner decisions that belong in the builder

Required direction:
- category- or type-based behavior only
- no permanent string-contains shaping rules

### 4. WorldCityTowers.tsx

Owns:
- tower render composition
- distinction between tower core and optional decorative/support layers

Does not own:
- skyline triage through hidden IDs as a permanent solution
- reserve contract definition

Required direction:
- preserve skyline identity through explicit composition, not accidental side effects

### 5. WorldCityMegaLandmarks.tsx

Owns:
- signature landmark silhouettes
- landmark family composition
- landmark-only subpart visibility decisions

Does not own:
- cleanup of source data generated by skeleton layout
- booth placement or booth reserve rules

Required direction:
- become the explicit owner of signature skyline silhouettes
- reduce broad hidden landmark part sets over time

### 6. ExpoRearCampusLayout.ts / ExpoRearCampus.tsx

Own:
- rear-campus source metrics
- stadium-side forecourts, pavilion families, landmark towers
- perimeter connectors and stadium-adjacent runtime structures

Do not own:
- city-side booth placement
- city builder suppression
- broad world cleanup outside stadium/rear-campus scope

Required direction:
- split perimeter connectors, venue massing, pavilion families, and local decorative choices clearly
- remove blanket empty-array suppression where source intent should decide visibility

### 7. WorldGroundPlane.tsx

Owns:
- global base ground only

Does not own:
- district decorative overlays
- perimeter stitching
- promenade or local forecourt identity

### 8. WorldCityPlanes.tsx

Owns:
- city plane rendering for accepted visible city-plane roles

Does not own:
- heuristic cleanup by plane name forever
- hidden filler layers used only to hide tone bugs

Required direction:
- consume typed plane roles from the builder

### 9. WorldPromenade.tsx

Owns:
- promenade-specific surfaces only when explicitly enabled by accepted ground hierarchy

Does not own:
- replacement for city ground
- broad mid-axis patching

### 10. Booth System

Files:
- `src/modules/expo/lib/boulevardLayout.ts`
- `src/modules/expo/layout-engine.ts`
- `src/modules/expo/runtime/booths/*`
- `src/modules/expo/components/BoothArchitectureKit.tsx`

Owns:
- booth slot resolution
- booth tier semantics
- booth visual assemblies
- booth-owned presentation screens

Does not own:
- world geometry
- rear-campus perimeter
- city mass/tower/landmark shaping

Exception:
- booth systems may consume the shared reserve contract for collision validation

## Freeze Rule For Booth Teams

Once a world checkpoint is accepted:
- booth branches may not edit:
  - `WorldCitySkeletonLayout.ts`
  - `WorldCitySkeleton.tsx`
  - `WorldCityMasses.tsx`
  - `WorldCityTowers.tsx`
  - `WorldCityMegaLandmarks.tsx`
  - `ExpoRearCampus.tsx`
  - `ExpoRearCampusLayout.ts`
  - `WorldGroundPlane.tsx`
  - `WorldCityPlanes.tsx`
  - `WorldPromenade.tsx`

If booth work discovers a world defect:
- stop
- file it as a separate world task
- repair it on a separate world branch

## Temporary Quarantine Policy

Allowed temporarily:
- small hidden ID sets
- small compatibility filters
- adapters from legacy categories to typed contracts

Not allowed as permanent architecture:
- giant hidden-ID graveyards
- broad pattern suppression replacing source-owner cleanup
- no-op reserve contracts
